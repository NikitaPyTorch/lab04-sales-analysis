# Контрольные вопросы к лабораторной работе № 4

Формулировки вопросов сохранены из методических указаний. Ответы относятся к этому проекту.

## 1. Чем List отличается от Set и Map?

`List` хранит последовательность элементов, сохраняет их порядок и допускает повторы; элемент можно получить по индексу. `Set` хранит уникальные элементы: одинаковое значение присутствует один раз. `Map` хранит пары «ключ → значение», и каждому ключу соответствует одно значение. Этим значением может быть список. В работе это список продаж, множество кодов покупателей и карты групп или сумм.

## 2. Почему уникальные коды покупателей удобно хранить в Set?

Один покупатель может совершить несколько продаж, но для списка уникальных покупателей его код нужен один раз. При добавлении кодов в `HashSet` дубликаты автоматически не увеличивают множество. Например, из всех продаж DemoData получаются C01, C02, C03 и C04. Порядок кодов для этой задачи не важен.

## 3. Зачем при сортировке создавать новый список?

По правилам работы исходный список изменять нельзя. `List.sort` переставляет элементы того списка, у которого вызван. Поэтому сначала создаётся `new ArrayList<>(sales)`, затем сортируется копия. После вызова исходные продажи сохраняют порядок, а контейнер результата независим от исходного. Объекты `Sale` можно не копировать, потому что они неизменяемы.

## 4. Как включить в период начальную и конечную даты?

Использовать условие «дата не раньше начала и не позже конца»:

```java
!sale.getDate().isBefore(from) && !sale.getDate().isAfter(to)
```

Дата, равная `from` или `to`, проходит обе проверки. Равные начало и конец задают корректный период в один день. Перед отбором проверяется, что обе даты заданы и начало не позже конца.

## 5. Что выполняют filter и collect в Stream API?

`filter` оставляет только элементы, для которых условие возвращает `true`. В нашем отборе это продажи в выбранном периоде. `collect` завершает обработку потока и собирает результат по правилам коллектора: например, `Collectors.toList()` — в список, `groupingBy` — в карту групп. Промежуточный `filter` сам по себе не создаёт готовую коллекцию результата.

## 6. Чем отличается список продаж по категориям от сумм по категориям?

Группировка имеет тип `Map<String, List<Sale>>`: можно посмотреть каждую исходную продажу категории. Итоги имеют тип `Map<String, Double>`: на категорию хранится одно число — сумма продаж. В этом проекте `groupByCategory` группирует весь переданный список, а `amountByCategoryForPeriod` сначала ограничивает даты. Например, во всей группе Office пять продаж, а её сумма за 1–5 сентября равна 190.

## 7. Как groupingBy и summingDouble работают вместе?

`groupingBy` выбирает ключ для каждой записи, например категорию. Переданный ему коллектор `summingDouble` складывает суммы записей внутри каждой группы:

```java
Collectors.groupingBy(
        Sale::getCategory,
        Collectors.summingDouble(Sale::getAmount))
```

Результат — карта «категория → сумма». Если вместо категории использовать `Sale::getDate`, получится карта итогов по дням. Группа с существующей нулевой продажей сохраняется со значением `0.0`; группа без записей не создаётся.

## 8. Почему суммы по категориям и по дням должны совпасть с общей суммой за тот же период?

Все расчёты используют одни и те же продажи периода. Каждая продажа имеет ровно одну категорию и одну дату, поэтому в каждом разбиении учитывается ровно один раз. Группировка меняет способ распределения записей, но не их состав.

Для 1–5 сентября суммы категорий `190 + 600 + 450` и суммы дней `70 + 500 + 460 + 150 + 60` равны общей сумме 1240. Для произвольных дробных значений `double` из-за ограниченной точности возможны малые различия в последних разрядах, поэтому числовые тесты используют допуск.
