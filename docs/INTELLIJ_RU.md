# Открытие и запуск в IntelliJ IDEA

Проект использует **JDK 25** и **Maven**. В `pom.xml` уже задан `maven.compiler.release = 25`, а JUnit подключён как тестовая зависимость. Исходные файлы и настройки Maven для запуска менять не нужно.

## Получить готовый проект с GitHub

1. Открой свой GitHub-репозиторий с выполненной работой. На его странице выбери **Code → HTTPS** и скопируй адрес.
2. На стартовом экране IDEA нажми **Clone Repository**; в некоторых версиях эта кнопка называется **Get from VCS**. В открытой IDEA доступна команда **File → New → Project from Version Control**.
3. Вставь адрес в поле URL, выбери папку и нажми **Clone**. При появлении запроса открытия выбери **Trust Project**.

Эти способы клонирования описаны в [инструкции JetBrains](https://www.jetbrains.com/help/idea/set-up-a-git-repository.html). Для выполненной работы используй свой GitHub-репозиторий; ссылка из методички ведёт на стартовый проект с незаполненными методами.

Если проект уже скачан или находится на компьютере, выбери **File → Open**, укажи его `pom.xml` и при запросе нажми **Open as Project**. IDEA откроет проект как Maven-проект и загрузит зависимости. [Открытие Maven-проекта](https://www.jetbrains.com/help/idea/maven-support.html).

## Проверить Java и импорт Maven

1. Открой **File → Project Structure → Project** (`Ctrl+Alt+Shift+S` на Windows).
2. Установи **Project SDK: JDK 25**. Если JDK ещё не добавлен, выбери добавление установленного JDK или его загрузку в списке SDK. Не выбирай JRE вместо JDK.
3. В настройках **Settings → Build, Execution, Deployment → Build Tools → Maven → Runner** проверь, что JRE использует Project JDK или JDK 25. При необходимости выбери тот же JDK в разделе **Maven → Importing**, поле **JDK for importer**. [Настройки JDK для Maven в IDEA](https://www.jetbrains.com/help/idea/maven-support.html#change_jdk).
4. Дождись завершения загрузки зависимостей и индексации. Если IDEA предлагает **Load Maven Changes**, нажми эту кнопку; также можно обновить проект кнопкой перезагрузки в окне **Maven**.

В окне Project должны быть доступны пакеты `by.bseu.pp.lab04` в `src/main/java` и `src/test/java`. Если Maven не распознан, заново открой именно `pom.xml` как проект.

## Запустить программу

2. Нажми зелёный треугольник рядом с методом `main` и выбери запуск `Application.main()`.

## Запустить все тесты

Нажми правой кнопкой на `src/test/java` или пакет `by.bseu.pp.lab04` внутри этой папки и выбери **Run Tests**. Название команды может содержать имя пакета. Для одной группы открой тестовый класс, например `PeriodFilterTest`, и нажми зелёный треугольник рядом с его именем. [Запуск JUnit-тестов в IDEA](https://www.jetbrains.com/help/idea/junit.html).

Другой способ — открыть окно **Maven**, раскрыть **Lifecycle** и запустить **test**. Maven скомпилирует основные классы и тесты, а Surefire выполнит проверки. Тесты можно запускать как средствами IDEA, так и через Maven. [Тестирование Maven-проекта](https://www.jetbrains.com/help/idea/work-with-tests-in-maven.html).

В предоставленном наборе **46 тестов**. Ожидаемый итог исправного запуска: все проверки прошли, нет ошибок и пропущенных тестов. Это инструкция проверки; факт успешного запуска подтверждается отдельным результатом выполнения.

Если тест красный, выбери его в окне Run и посмотри `Expected`, `Actual` или исключение. Если ошибка возникает до тестов, проверь SDK и загрузку Maven-зависимостей.

## Если запуск не получается

| Сообщение или симптом | Что проверить |
|---|---|
| `release version 25 not supported` или `invalid target release: 25` | Maven запускается под JDK старее 25: проверь Project SDK и Maven Runner |
| `UnsupportedClassVersionError` | Программа запускается под более старой Java: выбери JDK 25 в конфигурации запуска |
| Не находятся `org.junit.jupiter` или JUnit-тесты | Дождись загрузки зависимостей; обнови Maven-проект; проверь доступ к репозиторию зависимостей |
| Java-файлы видны, но нет нормального Maven-проекта | Открой корневой `pom.xml` через File → Open → Open as Project |
| Русские символы отображаются неверно | Проверь UTF-8 для файлов и консоли; кодировка исходников в `pom.xml` уже UTF-8 |

Для защиты открой `SalesAnalyzer.java`, запусти тесты и затем `Application`. Рядом можно держать `EXPLANATION_RU.md` и `CONTROL_QUESTIONS_RU.md`.
