## Задание

| Метод | Результат |
|---|---|
| `filterByPeriod` | Продажи за период включительно, в исходном порядке |
| `findByProductCode` | Все продажи с точным совпадением кода товара |
| `sortByAmountDescending` | Новый список по сумме по убыванию, при равенстве — по id по возрастанию |
| `uniqueCustomerCodes` | Set кодов покупателей без повторений |
| `groupByCategory` | Map категория → список продаж в исходном порядке |
| `totalAmountForPeriod` | Общая сумма продаж за период |
| `amountByCategoryForPeriod` | Map категория → сумма продаж за период |
| `amountByDateForPeriod` | Map дата → сумма продаж за период |

Используйте Stream API в `filterByPeriod`, `groupByCategory` и трёх методах
расчёта сумм. Остальные методы можно написать через цикл или Stream API.
Тесты проверяют результат, а использование Stream API нужно показать преподавателю в коде.

## Правила

- Список не изменяется. Результаты-коллекции — самостоятельные контейнеры.
  Объекты `Sale` неизменяемы; создавать их копии не нужно.
- Пустой список допустим. Нет результатов: пустая коллекция или сумма 0.
- `null` вместо списка или его элемента, неверный период и пустой код товара
  приводят к `IllegalArgumentException`; эти проверки уже реализованы.
- Начальная и конечная даты входят в период; равные даты допустимы.
- Код товара сравнивается через `equals`, с учётом регистра, без обрезания пробелов.
- Порядок ключей Map и элементов Set не задан; внутри групп порядок сохраняется.
- Повторяющиеся записи не удаляются при поиске, группировке и суммировании.
- Сумма продажи — `unitPrice * quantity`. Внутри методов не округляйте `double`.
  В выводе Application суммы форматируются до двух знаков.
- В итоговых Map есть только категории и даты с продажами в периоде. Продажа с
  нулевой суммой всё равно создаёт соответствующий ключ. Дни без продаж не добавляются.
